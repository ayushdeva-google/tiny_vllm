🎯 Key Comparative Insights & Hardware Bottleneck Analysis:
  • Elimination of O(N²) Quadratic Growth: In Without KV Cache, recomputing full sequence history caused attention latency to explode from 0.48 ms to 312.92 ms (407.06 ms total step latency). In With KV Cache, KV caching stores past key/value states, keeping linear projections strictly flat (~6.4 ms for SwiGLU, ~0.9 ms for QKV) and attention scaling gracefully as linear vector-matrix GEMV (~1.34 ms at step 2047, a 233.5× speedup).
  • Tier 1 Wall-Clock Bottleneck Shift (Host CPU Launch-Bound): In Without KV Cache, wall-clock time was 93.7% GPU-bound. In With KV Cache, because individual GPU micro-kernels finish in just 5–15 µs, the GPU completes all math in ~12 ms/tok and starves for ~43 ms waiting for the Python interpreter to enqueue kernels. Consequently, 56.6s (70.1%) of generation time is host CPU dispatch dead time.
  • Tier 2 Inside-GPU Bottleneck Inversion (Memory-Bandwidth Bound): In Without KV Cache, 93.1% of GPU time was spent crunching tensor arithmetic. In With KV Cache, single-token decode ($S=1$) reads 2.46 GB of weights for 1 vector multiply—an arithmetic intensity of only 1.04 FLOP/byte (vs. NVIDIA L4 ridge point of 400 FLOP/byte). Inside the GPU, execution has completely inverted from compute-bound to 93.8% memory-bandwidth bound.
  • Production Solutions: In production engines (such as vLLM and TensorRT-LLM), Kernel Fusion reduces kernel launches from 732 down to ~50, and CUDA Graphs replays the entire forward pass in a single 10 µs host invocation, cutting wall-clock decode latency down to ~12 ms/tok and pushing throughput to 80+ tok/s.

📖 Section E: Systems & Architecture Glossary
Clear definitions of physical hardware metrics, execution overheads, and architectural mechanisms profiled in this report, categorized by hardware metrics, KV-cache architecture, roofline mechanics, and production mitigations.
⚡ Active GPU Duty Cycle (%)
Core Hardware Metric

The percentage of wall-clock token generation time that the GPU execution units (Streaming Multiprocessors / SMs) were actively executing kernel instructions on silicon: (Total Active Kernel Time / Total Wall-Clock Time) * 100.

Without KV Cache vs. With KV Cache Delta: In Without KV Cache, duty cycle climbed from 31% to 98.6% as the GPU was drowned in quadratic recomputation. In With KV Cache, caching keys and values cut active execution to ~12 ms/tok, dropping duty cycle down to ~18–22% and exposing the host CPU dispatch bottleneck.
⏱️ Host CPU Launch & Driver Gaps
Core Hardware Metric

The measured dead time where GPU silicon sits completely idle with an empty pipeline waiting for the host CPU Python thread to enqueue the next CUDA kernel into the stream queue.

Root Cause: In unfused eager PyTorch, generating a single token requires ~732 individual kernel invocations. Because each micro-kernel finishes in ~5–15 µs while the host takes ~50 µs to execute Python bytecode and call cudaLaunchKernel, the GPU drains its work queue and starves for ~43 ms per token (69.3% of wall-clock time).
🔥 Active GPU Kernel Execution Time
Core Hardware Metric

The true elapsed silicon time spent by GPU Streaming Multiprocessors executing forward-pass operations, measured via CUDA hardware event timers with microsecond resolution.

Systems Impact: Active kernel execution dropped from 330.41 s (Without KV) down to 24.20 s (With KV) across 2,048 tokens—a massive 13.7× / 16.4× compute reduction (-92.7%) achieved purely through algorithmic activation caching.
📦 In-Place Contiguous KV Cache (KV_Cache_Update)
KV-Cache Architecture

A pre-allocated contiguous GPU VRAM buffer [B, n_kv_heads, max_seq_len, head_dim] dedicated to storing past Key and Value activation vectors across all 16 Transformer layers.

Performance Advantage: Rather than dynamically concatenating tensors with torch.cat (which triggers reallocation stalls and memory fragmentation), tiny_vllm performs in-place slice writes k_cache[:, :, pos:pos+1, :] = k_new, completing in just 0.035 ms with zero dynamic memory overhead.
🔍 Grouped-Query Attention (GQA) 4:1 Compaction
KV-Cache Architecture

LLaMA-3.2-1B groups 32 Query heads into 8 Key/Value heads (a 4:1 ratio). Each group of 4 query heads shares a single key and value head.

Memory Savings: Instead of caching 32 heads (131.1 KB/tok across 16 layers), GQA stores only 8 unrepeated heads, reducing the KV cache memory footprint by 75% to just 16.38 KB/tok (or 32.77 KB in FP16/BF16). For 2,048 tokens, the entire cache consumes only 33.55 MB in VRAM.
📐 Arithmetic Intensity & L4 Ridge Point (Roofline)
Roofline Mechanics

Arithmetic intensity measures the ratio of floating-point operations performed per byte of data transferred from GPU VRAM: FLOPs / Byte.

Memory-Bound Inversion: An NVIDIA L4 GPU delivers 120 TFLOPS of BF16 compute and 300 GB/s memory bandwidth, creating an operational ridge point of 400 FLOP/byte. Single-token decode ($S=1$) reads 2.46 GB of weights to compute ~2.46 GFLOPs—an arithmetic intensity of only 1.04 FLOP/byte. Consequently, the GPU spends 93.8% of its active time streaming weights rather than doing math.
🚀 CUDA Graph Replay & Kernel Fusion Mitigations
Production Mitigations

Production serving engines (such as vLLM and TensorRT-LLM) employ two key architectural techniques to overcome the 69.3% host CPU dispatch gap exposed in With KV Cache:

1. Kernel Fusion: Fuses RMSNorm, GEMM, SiLU, and addition kernels into unified CUDA kernels, reducing 732 launches to ~50.
2. CUDA Graphs: Records the entire token decode forward pass into an immutable hardware execution graph. The CPU launches the entire sequence in a single ~10 µs ioctl, pushing GPU duty cycle from ~22% to 95%+ and accelerating decode to 80+ tok/s.
🔬 Section F: Expected Results & Systems Invariants
The 5 physical and mathematical systems invariants governing stateful Key-Value cached inference on LLaMA-3.2-1B, verified against measured execution profiles.
📌 With KV Cache Systems Invariants & Architectural Checklist: Parameter counts, weight footprints, and cache dimensions are exact physical specifications of LLaMA-3.2-1B on NVIDIA L4 hardware. Unlike Without KV Cache's naive recomputation baseline, the findings below represent the mathematical and physical invariants governing stateful Key-Value cached inference.
🔬 Invariant 1: Constant O(1) Projections & SwiGLU MLP Execution
In Without KV Cache, linear projections processed the entire accumulated history ($S = t$ tokens), causing feed-forward layers to scale linearly with context length up to ~45 ms per step.

With KV caching, newly generated tokens are evaluated strictly one at a time ($S = 1$). Projections perform single-vector matrix multiplications (GEMV) rather than large matrix-matrix multiplies (GEMM):
  • W_q Projection: Strictly flat at ~0.58 ms from step 0 to step 2047 (~8.39 MB weights per layer).
  • W_k & W_v Projections: Strictly flat at ~0.16 ms each (~2.10 MB weights per layer, 4:1 GQA ratio).
  • SwiGLU Gate+Up: Strictly flat at ~4.31–4.34 ms across 2,048 tokens (~67.11 MB weights per layer).
  • SwiGLU Down: Strictly flat at ~2.10 ms across 2,048 tokens (~33.55 MB weights per layer).
Empirical Invariant: KV caching decouples linear projection latency from context length: projection times at token #2000 are identical to token #1!
⚡ Invariant 2: Linear O(t) Attention Scaling via Vector-Matrix GEMV
In Without KV Cache, full causal self-attention recalculated quadratic $O(t^2)$ matrix multiplications across all $t$ historical tokens, exploding from ~0.48 ms to 312.92 ms.

With KV caching, attention computes a single query vector ($1 imes D$) dot product against cached key vectors ($t imes D$), and multiplies the resulting attention distribution ($1 imes t$) with cached values ($t imes D$):
  • Step #250: Attention compute takes 0.38 ms (vs 2.36 ms in Without KV ➔ 6.2× faster).
  • Step #1000: Attention compute takes 0.77 ms (vs 102.44 ms in Without KV ➔ 133.0× faster).
  • Step #2047: Attention compute takes 1.34 ms (vs 312.92 ms in Without KV ➔ 233.5× faster!).
Empirical Invariant: Attention latency scales strictly linearly with context length $O(t)$, reducing attention compute time at token #2047 by an astonishing 99.6%!
📦 Invariant 3: GQA 75% Memory & Bandwidth Footprint Reduction
LLaMA-3.2-1B incorporates Grouped-Query Attention (GQA) with 32 Query heads and 8 Key/Value heads across 16 layers (head dimension $D=64$):
  • Per-Token Cache Size: $2\text{ (K+V)} \times 8\text{ heads} \times 64\text{ dim} \times 2\text{ bytes (BF16)} = 2,048\text{ bytes}$ per layer = 32.77 KB per token across 16 layers.
  • Total VRAM Buffer: At 2,048 tokens, the entire KV cache consumes only 33.55 MB of VRAM.
  • Footprint Reduction: Traditional Multi-Head Attention (32 KV heads) would require 134.2 MB. GQA achieves a 75% reduction in cache capacity and streaming bandwidth.
Empirical Invariant: The entire 2,048-token KV cache fits easily in GPU VRAM with negligible memory pressure, leaving >98% of VRAM available for model weights and activation buffers.
🚀 Invariant 4: Zero-Stall In-Place Slice Insertion (KV_Cache_Update)
Naive KV cache implementations append newly generated keys and values using dynamic concatenation (e.g. torch.cat([past, new], dim=2)). This forces the CUDA caching allocator to allocate a new memory block, copy old entries, and free previous buffers at every decode step.

tiny_vllm implements in-place slice insertion into pre-allocated contiguous buffers:
self.k_cache[:, :, start_pos:start_pos+1, :] = k_new
self.v_cache[:, :, start_pos:start_pos+1, :] = v_new
Empirical Invariant: The measured latency of KV_Cache_Update across all 2,048 tokens is consistently ~0.035 ms (<0.3% of step time), with 0 ms dynamic memory reallocation and zero memory fragmentation!
🔄 Invariant 5: The Dual Bottleneck Inversion (Macro & Micro Tiers)
Eliminating redundant quadratic compute triggers a profound dual inversion across hardware abstraction tiers:
  • Tier 1: Macro Wall-Clock Inversion (GPU ➔ Host-Bound):
    In Without KV Cache, wall-clock time was 93.7% GPU-bound (330.4s GPU vs 22.2s CPU gaps). In With KV Cache, active GPU time dropped to 24.2s. Because GPU micro-kernels complete in ~5–15 µs, the GPU empties its queue and waits on the host Python interpreter for 54.65s (69.3% idle gaps). The system has shifted from GPU-bound to host CPU launch-bound.
  • Tier 2: Micro Silicon Inversion (Compute ➔ Memory-Bound):
    In Without KV Cache, inside active GPU kernels, 93.1% of time was spent on Tensor Core arithmetic (307.7s compute vs 22.7s memory). In With KV Cache, single-token decode ($S=1$) requires streaming 2.46 GB of weights for only 1 vector dot product—an arithmetic intensity of only 1.04 FLOP/byte (vs. NVIDIA L4 ridge point of 400 FLOP/byte). Inside the GPU, execution is now 93.8% memory-bandwidth bound (22.7s memory streaming vs 1.5s compute).
Production Takeaway: In real-world inference engines (e.g. vLLM), Kernel Fusion reduces kernel count from 732 to ~50, and CUDA Graphs replays the entire forward pass in one ~10 µs dispatch—eliminating the 69.3% host CPU gap and driving decode throughput to 80+ tok/s.
