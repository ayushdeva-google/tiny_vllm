Axis 1 · Incoming Arrival Process

Frequency (λ QPS) & Burstiness (β)

Inter-arrival gaps follow Δt ~ Gamma(β, 1/(λ·β)) with a fixed seed (seed=42) so every batching optimization replays the exact same arrival timestamps:

  • Low QPS (0.15 req/s): Measures unloaded single-user TTFT & TPOT latency floor.
  • Knee QPS (0.35–1.0 req/s): Exposes M/G/1 head-of-line queueing blowup on B=1 while batched engines stay flat.
  • High QPS (2.5–10+ req/s): Finds the higher saturation knee of Static vs. Continuous Batching.
  • Offline Burst (λ = ∞): All requests arrive at t = 0s; measures pure max throughput (tok/s).
Axis 2 · Request Length Nature

5 Standard Workload Distributions

Batching optimizations behave very differently depending on length variance (Coefficient of Variation, CV):

  • sharegpt: Real prompts (37–990 in, 17–382 out). Industry standard (vLLM / Orca papers).
  • synthetic-uniform: ~128 in / ~64 out (CV ≈ 0.08). Isolates pure GEMV → GEMM speedup with zero padding waste.
  • synthetic-skewed: 75% short chat + 25% long RAG. Exposes static-batch padding waste & straggler tail wait.
  • prefill-heavy / decode-heavy: Separates compute-bound prefill stalls (ITL spikes) from HBM-bound KV/weight streaming.
Axis 3 · Engine Progression

Standalone Engine Stages

Each optimization stays an independent implementation evaluated against the exact same harness & SLOs (TTFT ≤ 2000ms, TPOT ≤ 50ms):

  • Stage 0 (Done): sequential_fcfs_b1 — 1 request at a time, pure PyTorch + static KV cache.
  • Stage 1 (Done): Static Padded Batching — batches up to B queued requests; waits for longest straggler in batch.
  • Stage 2 (Done): Continuous (Iteration-Level) Batching — retires finished requests & injects waiting requests every step.
  • Stage 3 (Next): Chunked Prefill / PagedAttention — eliminates ITL prefill stalls & KV fragmentation.
